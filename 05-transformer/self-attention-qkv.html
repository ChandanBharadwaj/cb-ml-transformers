Self-Attention: Q, K, V

This is the center of the course — the mechanism the whole curriculum has been walking toward. Two upgrades to M4.4's attention produce it: the sentence attends to itself (every word looks at every word), and each token gets three separately learned vectors for its three roles. Every piece of math on this page is something you already own: dot products (M1.2), matrices (M1.3), softmax (M3.2). Take it slowly anyway.

The goal: every word updates its meaning from context

Remember what M2.4 proved impossible for static embeddings: "bank" needs a different vector near "river" than near "loan". Self-attention is the machine that does that update — for every word simultaneously. Each token starts as its context-free embedding (last page) and leaves as a blend of the whole sentence, weighted by learned relevance. Run that a few layers deep and vectors stop meaning words and start meaning words-in-this-sentence.

Q, K, V: three jobs, three learned projections

Each token's embedding x is multiplied by three learned matrices — WQ, WK, WV — producing three vectors with distinct jobs. The search-engine metaphor is exact (and it is literally your RAG pipeline, shrunk into a sentence):

  • Query (q) — what I'm looking for: "I'm a verb; where are my subject and object?"
  • Key (k) — what I advertise: "I'm an animate noun, singular, subject-flavored."
  • Value (v) — what I hand over if selected: the actual content contributed to whoever attends to me.

Why three separate projections instead of using the raw embedding for everything (as 2015 attention did)? Because the roles genuinely differ: what a verb seeks (nouns) is unlike what it advertises (verb-ness), and what it contributes is different again. Remember M4.4's build, where the toy query couldn't tell Katze from Hund? Separate learned projections are exactly the fix — they let "relevance to me" become a trained, role-specific notion.

The full recipe, with real numbers

Attention(Q, K, V) = softmax(QKᵀ / √d) · V
In plain words: ① every query dots with every key (QKᵀ — the all-pairs score grid, M1.2's similarity matrix reborn); ② divide by √d — dot products of longer vectors grow bigger just from having more slots, and oversized scores would drive softmax to razor-sharp weights with dead gradients (M3.4!), so we shrink by the size factor; ③ softmax each row into weights; ④ blend the values. Real numbers

In MiniLM: d_model = 384, per-head dimension = 64 (next page), so W_Q, W_K, W_V are each 384×384 ≈ 147k parameters — ~442k per layer for the three, 2.65M across 6 layers. Cost of the score grid: a 512-token input builds a 512×512 attention matrix = 262,144 scores per head per layer — the O(n²) that M4.4 warned about, now concrete. Double the tokens → 4× the scores: the arithmetic reason long context costs what it costs (M11.2 prices it fully).

Connect the dots

The RAG mapping is now exact, one row deep: your user's question = query; your chunk index = keys; the chunks themselves = values; cosine scoring + top-k = a hard softmax. You have been running one step of attention as a distributed system — with MiniLM's frozen geometry as W_Q and W_K, and your vector DB as QKᵀ. The transformer just runs it inside the model, with learned projections, all pairs, many layers. When someone says "attention is all you need," they mean: this lookup, stacked.

Build: trace the walkthrough by hand, then in numpy
import numpy as np

def softmax(z):
    e = np.exp(z - z.max()); return e / e.sum()

d = 8
scores  = np.array([0.8, 3.1, 2.0, 2.9])        # q(chased)·k(each), the animation's ①
scaled  = scores / np.sqrt(d)                    # ②
w       = softmax(scaled)                        # ③
print("weights:", w.round(2))                    # → [0.14 0.33 0.22 0.31] ✓ matches!

V = np.array([[1.0, 0.0],                        # v(the)    — toy 2-D values
              [0.2, 0.9],                        # v(cat)
              [0.5, 0.5],                        # v(chased)
              [0.1, 0.8]])                       # v(mice)
print("new chased:", (w @ V).round(3))           # ④ the blend

# now feel WHY the √d scaling exists:
big = np.array([8, 31, 20, 29], dtype=float)     # unscaled scores at higher d
print("no scaling :", softmax(big).round(4))     # ≈ [0 0.88 0 0.12] — near-argmax, gradients dead
print("with scaling:", softmax(big/np.sqrt(64)).round(4))  # healthy spread

Guided worksheet (paper, 5 minutes): pick your own four scores, scale, softmax, blend — once by hand makes it permanent. Then the last two print lines show the √d story: without scaling, softmax saturates and learning stalls; with it, the weights keep useful gradients. A detail worth 90 seconds in any interview.

If you remember one thing

Self-attention = every token asks (q), advertises (k), and offers content (v) via three learned matrices; scores = all-pairs dot products, scaled by √d, softmaxed, and used to blend values — softmax(QKᵀ/√d)V. One parallel operation turns context-free vectors into contextual ones. The rest of the transformer is scaffolding around this move.

Interview questions

Walk through self-attention end to end. (THE interview question — have this cold.)

Each token's embedding is projected by three learned matrices into a query, key and value. All queries dot with all keys → an n×n score matrix; scores are divided by √d_k and softmaxed row-wise into attention weights; each token's output is its weight-blended sum of all value vectors. Output: one updated, context-aware vector per token, computed in parallel as softmax(QKᵀ/√d)V. Intuition: a differentiable content-addressed lookup where every token retrieves from every other.

Why three separate projections instead of using the embedding directly for all roles?

The three roles carry different information: what a token needs from context (query), how it should be findable (key), and what it should contribute when found (value) are semantically distinct — a verb seeks nouns, advertises verb-ness, contributes action-content. Separate learned projections let each be optimized independently; using raw embeddings (as 2015 attention did) conflates them and empirically limits what attention patterns can be learned. It also lets attention be asymmetric: A attending to B ≠ B attending to A.

Why divide by √d_k?

For random-ish vectors, dot products grow with dimension — variance scales with d_k — so raw scores at d=64+ are large, pushing softmax into its saturated regime: near-one-hot weights whose gradients vanish (softmax's flat shoulders), stalling learning. Dividing by √d_k normalizes score variance to ~1 regardless of dimension, keeping softmax in its responsive range. It's a numerical-health fix, cheap and critical — the paper's name for the whole operation is "scaled dot-product attention".

What's the complexity of self-attention and what are the practical consequences?

Time and memory O(n²·d) for sequence length n: every token scores against every token. Consequences: context windows are finite and expensive to extend; doubling context quadruples attention compute; long-context serving needs KV caching (M11.2) and kernel tricks (FlashAttention computes exactly the same result with much better memory traffic). Sub-quadratic alternatives (linear attention, state-space models) trade some quality/generality for scaling — active research frontier.

How does self-attention solve the problem static word embeddings couldn't?

Static embeddings assign one vector per word independent of usage (M2.4's "bank" problem — a representational limit). Self-attention makes each token's output vector a learned, weighted function of the entire sentence: the same input row produces different outputs in different contexts because the keys it meets differ. Stacked over layers, this yields fully contextual representations — which is why BERT-era models immediately dominated sense-dependent tasks.

Does a token attend to itself? Is that necessary?

Yes — position i's query scores against its own key like any other, and typically assigns itself meaningful weight (the animation's .22). It matters: the output must retain the token's own content, not just context (a blend of only-neighbors would erase identity). Residual connections (M5.5) add a second, stronger self-preservation path — the two mechanisms together keep "mostly me, updated by context" as the default behavior.
