The block: two moves, two wrappers

Stacking: what six floors buy

Why repeat the block? Because each pass is one round of gather-context-then-process, and rounds compound. Probing studies (running diagnostics on each layer's vectors) show a consistent progression — lower layers resolve local, surface-level structure; middle layers, syntax and grammatical roles; upper layers, semantics, coreference, and task-level abstractions. Layer 1's "bank" has glanced at its neighbors; layer 6's "bank" has settled into river-country with its whole clause accounted for. Composition, not repetition — the same reason M3.1 said depth beats width for hierarchy.

Connect the dots

You can now do something concrete you couldn't a week ago: open any Hugging Face model page, click "config.json", and know what you're looking at — including spotting why one model is slow (big L, big d), why another truncates your text (max_position_embeddings), and what "L6 vs L12" costs and buys (MiniLM-L12 exists: same width, double depth, ~2× slower, a bit more accurate — a trade you can now reason about instead of guessing).

Build: compute BERT-base's 110M parameters by hand
# every line is arithmetic you can check on paper
V, P, d, L, ffn = 30522, 512, 768, 12, 3072

emb = V*d + P*d + 2*d              # token + position + segment tables
attn_layer = 4*(d*d + d)           # W_Q, W_K, W_V, W_O with biases      (5.3-5.4)
ffn_layer  = d*ffn + ffn + ffn*d + d   # expand + compress, with biases  (5.5)
ln_layer   = 2 * 2*d               # two LayerNorms, each γ and β        (5.5)
block      = attn_layer + ffn_layer + ln_layer

total = emb + L*block + 2*d        # + final embedding LayerNorm
print(f"embeddings: {emb/1e6:.2f}M")       # ≈ 23.8M
print(f"per block : {block/1e6:.2f}M")     # ≈ 7.09M
print(f"total     : {total/1e6:.1f}M")     # ≈ 108.9M  ← the famous "110M" ✓

# now YOU: change the constants to MiniLM (30522, 512, 384, 6, 1536)
# and verify ≈22.7M. Then try Llama-3-8B's numbers for sport.

Matching a published parameter count from first principles is a rite of passage — after it, no model size will ever be a mystery number again, and M7.2's memory math becomes trivial (bytes = params × precision).

If you remember one thing

The block = [LayerNorm → attention → +residual] then [LayerNorm → FFN → +residual], shape-preserving, stackable. A transformer is: embeddings + positions → the block × L → output. MiniLM-L6 is literally this block six times at width 384 — a diagram you can now draw, parameter-count, and read from its config file.

Interview questions

Draw/describe a transformer encoder block from memory.

Input: n token vectors of width d. Sublayer 1: LayerNorm, multi-head self-attention, output added to the input (residual). Sublayer 2: LayerNorm, position-wise FFN (d → 4d → GELU → d), again residual-added. Output: n × d, same shape, feeding the next identical block. Attention is the only cross-token operation; the FFN is per-token; the residual stream carries state through the whole stack.

Why must the block preserve its input shape, and what does that enable?

The residual addition x + f(x) requires f(x) to match x's shape, and stacking requires each block's output to be a valid input to the next. This closure makes depth a free hyperparameter — 6 or 96 layers with zero architectural change — and enables tricks that exploit uniformity: layer pruning/early exit, pipeline parallelism across layers (M7.3), and depth-based distillation (M9.4's L6-from-L12 story).

What changes between layer 1 and layer 6 of an encoder, functionally?

Weights are separate per layer (no sharing in standard transformers), and learned function differs systematically: probing shows lower layers capture surface/local patterns, middle layers syntax, upper layers semantics and coreference — each block is another round of gather-then-process, so abstraction compounds. Practical consequences: middle-layer representations often transfer best for similarity tasks, and last-layer ones for classification — and sentence-embedding models choose their pooling layer accordingly (M9.1).

Given a config.json, estimate the parameter count.

Embeddings ≈ vocab×d (+ positions×d if learned). Per block: attention 4d² + FFN 2×d×d_ffn (≈ 8d² at the standard 4× ratio) ≈ 12d² total. Total ≈ vocab×d + L×12d². Sanity checks: BERT-base ≈ 23.8M + 12×7.1M ≈ 109M ✓; the formula also shows why doubling d roughly quadruples layer cost (d²) while doubling L only doubles it — a scaling intuition interviewers probe.

MiniLM-L6 vs MiniLM-L12: how do you choose, and what exactly differs?

Same width (384), same heads, same vocab — only depth differs: 6 vs 12 blocks, so ~2× the non-embedding compute and latency for L12, with modest quality gains (≈1–3 points on retrieval benchmarks). Choose by the bottleneck: embedding millions of documents or CPU-serving → L6; scoring quality on hard domains with GPU headroom → L12 or a larger family. The honest engineering answer is "benchmark both on YOUR recall@k" (M9.5's method).
