Matrices Transform Meaning

Last page, a dot product compared two vectors. This page: a matrix is a machine made of dot products — it takes a vector in and produces a transformed vector out. Why care? Because a neural network layer is a matrix. When someone says "MiniLM has 22 million parameters", they mean: the numbers filling its matrices. When a model is "trained", those matrix entries are what change. You are one page away from knowing what a parameter physically is.

Matrix × vector: every output is a weighted mix

A matrix is a grid of numbers. Multiply matrix W by a vector x, and each entry of the output is one row of W dot-producted with x. That's the whole rule — the operation from last page, repeated once per row.

y = W x   →   yᵢ = (row i of W) · x
In plain words: each output slot is a weighted mix of all input slots, and row i of the matrix holds the mixing weights for output slot i. A matrix is a recipe book: one recipe (row) per output ingredient.

A matrix is a transformation of space

Rows-of-dot-products is the mechanical view. The geometric view: a matrix moves every point in space at once — rotating, stretching, squashing, shearing. Feed in all the points of a shape and the matrix transforms the whole shape in one consistent way. This is the view that explains what layers do: each layer of a network warps meaning-space, step by step, until things that should be treated the same end up near each other.

Matrix × matrix: a batch of vectors at once

Stack several vectors as the rows of a matrix X (one row per sentence, say), and X·Wᵀ transforms all of them in one shot. That's not a new operation — just many matrix-vector products laid side by side. But it's the reason GPUs exist in this field: one big matrix-matrix multiply is vastly faster than thousands of little ones done one at a time. "Batching" (M7) is exactly this trick.

Shape discipline: the one skill to drill

Matrix multiplication (n×d) · (d×k) → (n×k) only works when the inner dimensions match — the d's touch and cancel. This sounds like pedantry; it is actually the #1 practical skill for reading any model code, because every layer, every attention head, every LoRA adapter is documented by its shapes.

So what is a "parameter"?

Now you can answer precisely: a parameter is one number inside one of the model's matrices (or bias vectors — M3). A "layer" is (mostly) a matrix waiting to transform whatever vector arrives. A "22M-parameter model" is a specific stack of matrices whose entries were tuned by training. Nothing more exotic than that.

Real numbers: counting MiniLM's parameters

One attention projection matrix inside all-MiniLM-L6-v2 is 384×384 = 147,456 parameters. Each of its 6 blocks has four of those (Q, K, V, output — M5) plus two FFN matrices of 384×1536 and 1536×384 (589,824 each). Blocks alone: ≈ 10.6M parameters. Add the token embedding table (30,522 words × 384 ≈ 11.7M — yes, the dictionary is half the model!) and you land near the advertised 22.7M. You'll do this bookkeeping yourself for BERT in M5 — it's oddly satisfying.

Connect the dots

You've written df.values @ weights in pandas/numpy without ceremony — that @ is this page. And when you download a model from Hugging Face, the multi-GB model.safetensors file contains literally nothing but these matrices, serialized. Model file = matrices. Forward pass = your data flowing through them, being dot-producted and warped, layer by layer.

If you remember one thing

A matrix is rows of dot products — equivalently, a warp applied to all of space. Models are stacks of matrices; parameters are their entries; training tunes them. And shapes must chain: (n×d)·(d×k)→(n×k). With that, model architecture diagrams stop being decoration and become readable.

Interview questions

What is a parameter in a neural network, concretely?

A single learned number — an entry in a weight matrix (or bias vector). A "7B model" contains seven billion such numbers organized into the matrices of its layers. Training adjusts their values; inference just multiplies data through them.

Why is matrix multiplication the dominant operation in deep learning?

Because a layer's job — "make each output a learned weighted mix of all inputs" — is exactly what matrix multiplication computes, and because it batches: one (batch×d)·(d×k) multiply processes the whole batch in a single, highly parallel operation that GPUs are built to accelerate. Transformers are ~99% matrix multiplies by compute.

A layer maps 384-D vectors to 1536-D. What's its weight matrix shape and parameter count?

Shape 384×1536 (or transposed, by convention) = 589,824 weights, plus 1536 bias terms ≈ 591k parameters. This is the actual expansion layer in each MiniLM block. Being able to do this arithmetic instantly is how you sanity-check model sizes and memory needs (M7).

Why can't two matrices multiply if the inner dimensions differ?

Each output entry is a dot product between a row of the first and a column of the second — dot products need equal-length vectors. Mismatched inner dimensions mean those rows and columns don't pair up, so the operation is undefined. (In practice: shape errors are the most common bug in model code, and reading them well is a superpower.)

Is a stack of two matrix multiplications more expressive than one?

Not by itself — W₂(W₁x) = (W₂W₁)x collapses into a single matrix. Depth only adds power when a nonlinearity sits between the matrices (M3's "bend"). This is exactly why activation functions exist, and it's a classic interview question.
