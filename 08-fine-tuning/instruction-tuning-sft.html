Instruction Tuning (SFT)

The page that explains the difference between GPT-3 and ChatGPT. A base model (M6.3) is a brilliant text-continuer with no concept of being spoken to. Supervised fine-tuning (SFT) on (instruction, response) pairs is what converts it into something that answers — and the chat template it learns is literally what your API calls serialize into. After this page, "system prompt" stops being folklore.

Base vs assistant: same weights family, different distribution

The mechanics: demonstration data, loss on the answer

SFT is M8.2's recipe applied to a decoder with one twist. Data: thousands to millions of (instruction, ideal response) pairs — human-written (expensive, the original InstructGPT way), synthetic (generated by a stronger model — "distilled" datasets like Alpaca's), or mined and cleaned. Training: ordinary causal-LM next-token prediction (M5.7), but with the loss masked to the response tokens only — the model reads the instruction but is only graded on its answer. A few thousand high-quality pairs measurably change behavior; the LIMA paper's famous claim: ~1,000 excellent examples beat far larger sloppy sets. Quality over quantity, again (M8.2's 80%).

Chat templates: what your API call actually becomes

Conversations aren't native to a token stream — they're serialized into one with special markers, and the model is SFT'd on exactly that format. Llama-3's actual template for a two-turn exchange: 

<|begin_of_text|><|start_header_id|>system<|end_header_id|>
You are a helpful assistant.<|eot_id|>
<|start_header_id|>user<|end_header_id|>
How do I center a div?<|eot_id|>
<|start_header_id|>assistant<|end_header_id|>

That's what messages=[{"role": "system", ...}, {"role": "user", ...}] compiles to. Three consequences worth engraving: (1) the "system prompt" is just tokens in a privileged-by-convention position — its authority comes entirely from SFT examples where system instructions were followed; nothing architectural enforces it (the security implications are M11.6's whole topic). (2) generation stops when the model emits <|eot_id|> — "knowing when to stop talking" is a trained behavior. (3) using the wrong template with a model (or none) silently degrades it — a real, common production bug when self-hosting.

What SFT can and cannot fix

Calibrate expectations like an engineer: SFT is excellent at format and style (JSON output, tone, structure — it IS imitation learning), good at task patterns (summarize-then-list, chain-of-thought habits), weak at adding knowledge (a few thousand pairs cannot outweigh trillions of pretraining tokens — facts belong in RAG, M8.6), and wrong for truthfulness in a subtle way: SFT teaches "produce answers shaped like the demonstrations" — including confident-sounding ones when the model doesn't know. Teaching calibrated behavior ("say you're unsure") needs preference-based training — which is precisely the cliffhanger for the next page.

Real numbers

InstructGPT (the paper behind ChatGPT's method): the SFT stage used just ~13,000 human demonstrations on a 175B base — 0.000004% of pretraining data volume, transformative behavior change. LIMA: 1,000 curated pairs on a 65B base produced a credible assistant. Alpaca: 52k synthetic pairs, <$600 total (generation + training) to chat-tune a 7B in 2023 — the moment DIY instruction-tuning became a weekend project. The lesson across all three: behavior is cheap to steer; competence was the expensive part (M6.1).

Connect the dots

Debugging superpowers unlocked: when your chatbot ignores the system prompt, you now know it's a training-strength issue (how heavily that model's SFT weighted system-following), not a syntax error on your side. When a self-hosted model outputs garbage, your first check is now the chat template (tokenizer.apply_chat_template). And when you write few-shot examples into a system prompt, you're doing micro-SFT at inference time (M6.3's in-context learning) — same principle, no gradients. The stack of "behavior-shaping layers" on top of one base model is now fully legible to you.

Build: see the template, then the transformation
from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("meta-llama/Llama-3.2-1B-Instruct")
msgs = [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "How do I center a div?"},
]
print(tok.apply_chat_template(msgs, tokenize=False, add_generation_prompt=True))
# ↑ the EXACT string your API calls become — special tokens and all

# then experience the base-vs-instruct gap yourself:
from transformers import pipeline
for name in ["meta-llama/Llama-3.2-1B", "meta-llama/Llama-3.2-1B-Instruct"]:
    gen = pipeline("text-generation", model=name, max_new_tokens=60)
    out = gen("How do I center a div in CSS?")[0]["generated_text"]
    print("\n" + "="*30, name.split("/")[-1], "\n", out)

Same 1B parameters, night-and-day behavior — the whole page in one diff. Keep apply_chat_template in your toolkit: it's the canonical answer to "what is the model actually seeing?", which is where half of all prompt debugging should start.

If you remember one thing

SFT = supervised fine-tuning on (instruction, response) demonstrations, loss on the response — it converts a text-continuer into an assistant by reshaping which continuations are probable. Chat is a serialization format the model was trained on; system-prompt authority is learned, not enforced; and SFT buys format and style, not knowledge or honesty. For "which of five decent answers is best" — turn the page.

Interview questions

What exactly changes between a base model and its -Instruct version?

Weights are further trained (SFT, usually + preference tuning) on demonstration conversations serialized in a chat template — same architecture, same pretraining. The output distribution shifts from "likely internet continuation" to "likely assistant response": answering rather than continuing, following formats, respecting role markers, emitting stop tokens. Capability is largely inherited; behavior is what's purchased — for ~0.001% of pretraining's cost.

Why is loss masked to response tokens during SFT?

The instruction/prompt tokens are context the model should condition on, not text it should learn to generate — training on them would teach the model to produce user-like questions and system-prompt boilerplate, wasting capacity and polluting behavior. Masking focuses the gradient purely on "given this context, produce this response." (Implementation: labels = -100 on non-response positions in HF.) Same logic as only grading a student's answers, not their copy of the exam questions.

What gives the system prompt its authority?

Nothing architectural — it's ordinary tokens at a conventional position. Authority comes from training data: SFT/preference examples where system-role instructions were consistently obeyed, including when user turns tried to override them. Consequently it's probabilistic, varies by model and training strength, and can be defeated by adversarial inputs (jailbreaks/injection — M11.6). Engineering corollary: system prompts are strong steering, not access control — never rely on them as a security boundary.

Why can't SFT reliably add new knowledge to a model?

Scale mismatch: a few thousand fine-tuning examples versus trillions of pretraining tokens — the gradient pressure to encode new facts is tiny, and pushing hard enough to force them in risks catastrophic forgetting (M8.1). SFT efficiently reshapes BEHAVIOR (formats, styles, patterns — richly represented in even small sets) but facts need either massive continued pretraining or, far more practically, retrieval at inference (RAG). "Style in the weights, facts in the context" is the operational rule (formalized in M8.6).

A self-hosted instruct model performs far worse than the same model on a hosted API. First suspects?

(1) Chat template mismatch — raw prompts or a wrong template instead of apply_chat_template: the model sees a format it was never trained on (the #1 cause). (2) Missing/incorrect stop tokens — outputs run on or truncate. (3) Sampling defaults differ (temperature/top-p, M11.1). (4) Quantization quality loss if running a heavily compressed variant (M11.3). (5) The API actually serves a different/updated checkpoint. Debug order: print the exact token stream in, then compare sampling configs — template errors are found in minutes once you look.
