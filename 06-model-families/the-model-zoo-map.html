The Model Zoo Map

Module capstone: turn family knowledge into navigation skill. Hugging Face hosts a million-plus models; interviews ask "which model would you pick and why"; and both are easy once you see the zoo as one family tree with three branches and a handful of naming conventions. This page is the map, the model-card reading protocol, and your decision cheat-sheet.

The family tree, 2013 → now

Reading a model card like a mechanic

Five questions, in order, answerable from any decent Hugging Face model card:

  1. Architecture & size — which branch (check config.json: is there a causal mask? enc+dec?), how many parameters (memory and latency, via M7.2's math).
  2. Objective & training data — MLM/causal/contrastive? on what corpus, with what cutoff and languages?
  3. Checkpoint stage — base (raw pretrain — completes text, doesn't chat), instruct/chat (M8.3–8.4 applied), or task-tuned (like all-MiniLM's contrastive stage)? Downloading a base when you need instruct is the classic beginner faceplant.
  4. Evals — which benchmarks, and are they the right ones for your task (M11.4's skepticism applies)?
  5. License — Apache/MIT (free), Llama-style community licenses (restrictions), research-only. This one ends projects; check it first in commercial work.

Decoding model names

Names are compressed spec sheets. Llama-3.1-70B-Instruct: family + version + 70 billion parameters + chat-tuned. all-MiniLM-L6-v2 (fully decoded at last): "all" = trained on all 1B+ sentence pairs of the sentence-transformers project; "MiniLM" = Microsoft's distilled architecture (M9.4); "L6" = 6 layers; "v2" = second training recipe. bge-large-en-v1.5: BAAI general embedder, large size, English, v1.5. Suffixes that matter: -Instruct/-Chat (tuned to converse), -Base (raw), -GGUF/-AWQ/-GPTQ (quantized formats, M11.3), distil- (M9.4's technique). What "B" buys — capability vs cost — is exactly M7's business, next module.

Real numbers: the zoo at a glance

Encoder branch (understand/embed): MiniLM 22M · BERT-base 110M · bge-large 335M — the branch tops out small because vectors don't need trillion-token worldliness. Decoder branch (generate): Qwen-0.5B → Llama-3-8B → 70B → frontier 100B–1T+. Enc-dec: Flan-T5 60M–11B, Whisper 1.5B. Rule of thumb from the spread: representation is cheap, generation is expensive, and a 5,000× size gap between your embedder and your LLM is normal architecture — your own stack is proof.

Connect the dots

Next time you're on a model page, run the five questions live — you'll notice you now recognize every field: config.json (M5.6), tokenizer files (M5.1), the safetensors sizes (M1.3: matrices, serialized), benchmark tables (M3.6's skepticism + M11.4 soon), and the base-vs-instruct distinction (M6.3's build showed you the raw behavior). Build: audit three model cards with the protocol
from huggingface_hub import model_info

for name in ["sentence-transformers/all-MiniLM-L6-v2",
             "meta-llama/Llama-3.1-8B-Instruct",
             "urchade/gliner_medium-v2.1"]:
    info = model_info(name)
    print("\n" + "="*60, "\n", name)
    print("  downloads/mo:", f"{info.downloads:,}")
    print("  license     :", getattr(info.card_data, "license", "?"))
    print("  tags        :", [t for t in info.tags[:8]])

Then open each card in a browser and answer the five questions in writing — ten minutes total. The MiniLM card especially rewards a re-read now: its training-data table, pooling description, and "intended uses" section are all M9 previews you can already mostly decode.

If you remember one thing

One tree: word2vec → transformer → three branches (encoder/MLM, decoder/causal, enc-dec/denoising) → everything else is recipe, scale and tuning stage. Read any model via five questions — branch & size, objective & data, checkpoint stage, evals, license — and never confuse a base model with an assistant again.

Interview questions

You need (a) semantic search, (b) a support chatbot, (c) transcription. Name model families and why.

(a) Encoder-branch embedder — MiniLM/bge class: bidirectional context, vectors as output, cheap at volume; plus optionally a cross-encoder reranker (M12.2). (b) Decoder-branch instruct model — Llama/Qwen/frontier API: generation + instruction-following; RAG on top for current knowledge. (c) Enc-dec Whisper-class: full audio encoded bidirectionally, text decoded with cross-attention. Bonus point for noting (a) and (b) coexist in one product — different branches for different layers.

What's the difference between a base and an instruct checkpoint, practically?

Base: raw pretrained next-token predictor — continues text, won't reliably answer questions, follow instructions, or refuse anything; intended as a substrate for further tuning or research. Instruct/chat: same weights pushed through SFT (+usually preference tuning) so it answers, follows formats, and behaves like an assistant. Practical failure mode: pointing a product at a base checkpoint and concluding "the model is bad." Always check the suffix and the card's stage.

Why do embedding models stay small (20M–350M) while chat models grow to hundreds of billions?

Task demands differ: an embedder must map text into a well-shaped similarity space — largely a language-structure task where bidirectional context and contrastive tuning (M9) matter more than encyclopedic knowledge or reasoning depth. Generation quality, world knowledge and reasoning scale strongly with parameters (M7.4). Economics reinforce it: embedders run per-document over entire corpora (cost scales with data), chat models per-conversation. Different scaling pressures → a 1000× size gap that's correct, not accidental.

Decode "all-MiniLM-L6-v2" and "Llama-3.1-70B-Instruct" fully.

all-MiniLM-L6-v2: sentence-transformers model trained on the "all" collection of 1B+ text pairs (contrastive, M9.3), MiniLM architecture (deep self-attention distillation from a larger teacher, M9.4), 6 transformer encoder layers (M5.6), second recipe version. Llama-3.1-70B-Instruct: Meta's Llama family, generation 3.1, 70 billion parameters, instruction/chat-tuned (M8.3–8.4) decoder-only model. Being able to unpack names into architecture + training story is exactly the fluency this module builds.

What do you check FIRST on a model card for commercial use, and what trips teams up?

License. Trip-ups: "open" ≠ permissive (Llama licenses carry use restrictions and user thresholds), research-only models leaking into production, embedding models trained on datasets with their own terms, and GGUF re-uploads inheriting (or mislabeling) the original license. Second check: the checkpoint stage (base vs instruct). Third: eval relevance to your task. An engineer who says "license first" signals production scars — in a good way.
